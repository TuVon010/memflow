# MemFlow 编码规范与命名约定

本文档定义 MemFlow 项目的代码风格、命名规则和注释规范，所有贡献者需遵循，以保持代码库的一致性与可读性。

---

## 1. 基础风格指南 (Effective Dart)

项目严格遵循 Dart 官方推荐的 [Effective Dart](https://dart.dev/guides/language/effective-dart) 规范，以下为核心要点摘要。

### 1.1 格式
- 使用 2 个空格缩进，禁止使用 Tab。
- 每行字符数建议不超过 80，硬限制 120。
- 使用 `dart format` 自动格式化所有 Dart 文件。
- 花括号风格：控制流语句左花括号不换行，右花括号另起一行。

### 1.2 导入
- 导入顺序：`dart:` 包 → `package:flutter/` → `package:` 包 → 相对路径导入。
- 避免使用 `show` / `hide` 重命名，除非解决冲突。
- 在文件头部使用 `export` 统一导出库的公共 API。

### 1.3 代码组织
- 一个类一个文件（除非是非常小的辅助类）。
- 私有成员使用下划线 `_` 前缀。
- 保持函数简短，单一职责。

---

## 2. 文件与文件夹命名规则

### 2.1 文件夹
- 全部小写，使用下划线分隔单词：`data/`, `review/`, `ai_generate/`。
- 按功能模块分目录：`features/`, `engine/`, `services/`, `widgets/`。
- 测试文件夹与源文件路径镜像：`test/engine/scheduler_test.dart` 对应 `lib/engine/scheduler.dart`。

### 2.2 Dart 源文件
- 使用下划线小写命名：`review_screen.dart`, `deck_repo.dart`。
- 文件命名应表明其内容类型：
  - `_screen.dart` — 页面 / 路由入口
  - `_provider.dart` — Riverpod 提供者
  - `_repo.dart` — 数据仓库
  - `_service.dart` — 业务逻辑服务
  - `_model.dart` — Isar 模型文件（由生成器生成，但原始定义如此）
- 如果一个文件包含一个主要的类，文件名应与类名一致（转换为下划线格式）。

### 2.3 资源文件
- 图片、字体等放在 `assets/` 下，按类型分子目录。
- 文件命名：小写 + 下划线，如 `logo_app.png`, `card_front_placeholder.png`。

---

## 3. 标识符命名约定

| 类型 | 风格 | 示例 |
|------|------|------|
| 类、枚举、混入 | 大写驼峰 (PascalCase) | `ReviewState`, `AIUsageLog` |
| 变量、参数、函数、方法 | 小写驼峰 (camelCase) | `dailyNewCardLimit`, `loadTodayQueue()` |
| 常量（`const` / `static const`） | 全大写 + 下划线 | `MAX_RETRY_COUNT`, `DEFAULT_EF` |
| 私有成员（类内） | 小写驼峰 + 前导下划线 | `_apiKey`, `_handleResponse()` |
| 泛型类型参数 | 单个大写字母 (E, T, K, V) | `List<T>`, `Provider<T>` |
| 扩展 | 大写驼峰 | `extension DateTimeFormat on DateTime` |

### 3.1 特殊约定
- 布尔变量/属性使用 `is`、`has`、`should` 前缀，如 `isLoading`、`hasError`、`shouldRetry`。
- 回调函数参数使用 `onXxx` 格式，如 `onTap`, `onRatingChanged`。
- 集合变量使用复数名词，如 `cards`, `tags`。

## 4. 注释规范

### 4.1 文档注释 (`///`)
- 所有公开的类、成员、方法必须包含文档注释，说明其用途、参数和返回。
- 使用 Markdown 格式增强可读性。
- 示例：
```dart
/// 根据用户评分调度卡片的间隔重复算法。
///
/// 接收当前的 [ReviewState] 和用户评分 [rating]，
/// 返回更新后的 [ReviewState] 供持久化存储。
///
/// 参数 [interviewMode] 若为 true，将根据面试倒计时调整间隔。
/// 返回的新状态包含下次复习时间和更新后的 EF。
ReviewState scheduleReview(ReviewState state, int rating, {
  bool interviewMode = false,
  double cardPriority = 0.0,
}) { ... }
```

### 4.2 代码内注释 (`//`)
- 用于解释复杂的业务逻辑、临时解决方案或 TODO。
- 保持简洁，紧挨相关代码上方。
- 使用 `// TODO:` 标记未来需要完成的工作，格式：`// TODO(username): 描述`。

### 4.3 文件头注释
- 每个 Dart 文件开头可包含一个简短说明（可选），格式为：
```dart
/// MemFlow 复习调度引擎
///
/// 实现 SM-2 改良算法，用于计算卡片的复习间隔。
```

## 5. 代码质量保证

- 使用 `flutter analyze` 执行静态分析，提交前必须零警告/错误。
- 使用 `dart format` 格式化代码，确保格式统一。
- 新功能或重要修改需附带单元测试或 widget 测试。
- 提交前确保所有现有测试通过 (`flutter test`)。

---

遵循以上规范，能够提升项目的可维护性，降低协作成本。如对规范有改进建议，欢迎通过 Issue 或 PR 提出。
