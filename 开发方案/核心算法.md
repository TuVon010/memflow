# MemFlow 核心算法说明 v1.0

## 1. 概述

MemFlow 的复习调度基于 **SM-2 改良算法**，并针对代码类记忆与面试冲刺场景进行了适配与增强。本文档详细说明算法的参数定义、评分映射、间隔与难度系数更新逻辑、每日复习队列生成规则、面试倒计时模式下的新卡插入策略，以及可选的遗忘风险预判机制。

---

## 2. SM-2 改良算法

### 2.1 状态参数

每个 `ReviewState` 记录持有以下调度相关字段：

| 参数 | 类型 | 说明 | 初始值 |
|------|------|------|--------|
| `difficultyFactor` (EF) | double | 难度系数，反映卡片的主观难易程度，影响间隔增长速率 | 2.5 |
| `interval` | int | 当前间隔（天），两次复习之间的时间 | 1 |
| `repetitions` | int | 连续成功复习次数（评分 ≥ 3 的次数） | 0 |
| `due` | DateTime | 下次复习到期时间 | 当前时间 |
| `lastReview` | DateTime? | 上次复习时间 | null |
| `reviewLog` | List\<ReviewLogEntry\> | 历史评分记录，每条包含时间、评分、耗时 | [] |

### 2.2 用户评分与质量映射

用户在复习时对每张卡片给出主观评分：

| 用户按钮 | 含义 | 内部质量分 `q` | 影响 |
|----------|------|----------------|------|
| 生疏 (Again) | 完全遗忘 | 0 | 重置间隔，降低 EF |
| 犹豫 (Hard) | 回忆困难，看到答案后能确认 | 3 | 间隔增长较慢，EF 微降或不变 |
| 顺畅 (Good) | 轻松回忆 | 5 | 间隔正常增长，EF 提升 |

### 2.3 核心调度算法伪代码

```
function scheduleReview(state, rating, interviewMode, cardPriority):
    q = mapRating(rating)   // 0, 3, 5
    
    // 1. 更新难度系数 EF
    if q >= 3:
        // 成功回忆：EF 根据质量分调整
        newEF = state.EF + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02))
        state.repetitions += 1
    else:
        // 遗忘：EF 惩罚
        newEF = state.EF - 0.2
        state.repetitions = 0
    
    // EF 边界保护
    newEF = max(newEF, 1.3)
    state.EF = newEF
    
    // 2. 计算新间隔
    if q == 0:
        newInterval = 1          // 完全遗忘，明天再复习
    else:
        if state.repetitions == 1:
            newInterval = 1      // 第一次成功，1 天后
        else if state.repetitions == 2:
            newInterval = 6      // 第二次成功，6 天后
        else:
            // 常规间隔 = 上次间隔 × EF
            newInterval = round(state.interval * newEF)
    
    // 3. 面试倒计时模式调整（可选）
    if interviewMode and cardPriority >= 0.8:
        // 高优先级卡片缩短间隔 20%，但不得低于 1 天
        newInterval = max(1, floor(newInterval * 0.8))
    
    // 4. 写入状态
    state.interval = newInterval
    state.due = now + Duration(days: newInterval)
    state.lastReview = now
    
    // 5. 记录日志
    state.reviewLog.add(ReviewLogEntry(
        date: now,
        rating: rating,
        elapsedMs: elapsed
    ))
    
    return state
```

### 2.4 参数说明与设计理由

- **EF 更新公式**：沿用标准 SM-2 公式，`0.1 - (5-q)*(0.08+(5-q)*0.02)`，当 q=5 时 EF 增加 0.1，q=3 时几乎不变，q=0 时直接扣减 0.2。这使得 **顺畅的卡片间隔快速拉长，遗忘的卡片立即变频繁**。
- **EF 下限 1.3**：防止卡片因多次遗忘进入极度密集的复习循环（例如 EF 降到 1.0 会导致间隔永不增长）。1.3 是经验值，保证最难的卡片也至少有 1.3 的增长因子。
- **阶梯间隔**：前两次成功不直接使用 `interval * EF`，而是强制 1 天和 6 天。这是为了防止新卡因偶然一次顺畅就跳过早期关键巩固期。
- **遗忘重置**：一旦评分生疏，`repetitions` 直接归零，间隔降为 1 天，相当于重新开始学习该卡片。

## 3. 每日复习队列生成算法

### 3.1 输入与输出

- **输入**：当前用户设置（每日新卡上限、面试模式状态、卡组优先级）、本地数据库。
- **输出**：一个有序的 `List<ReviewItem>`，包含今日需要复习的全部卡片。

### 3.2 队列生成步骤

```
function generateQueue(settings):
    now = DateTime.now()
    
    // 1. 取出所有过期的已学卡片
    dueCards = query ReviewState 
               where due <= now 
               order by due ASC
               
    // 2. 取出从未学习过的新卡片
    newCards = query Card 
               where id not in (select cardId from ReviewState)
               
    // 3. 若开启面试倒计时，按优先级排序
    if settings.interviewMode:
        // 结合卡片 difficulty 与所属卡组 priority 计算排序权重
        newCards = newCards order by 
                   (card.difficulty * 0.6 + deck.priority * 0.4) DESC,
                   card.createdAt ASC
    else:
        newCards = newCards order by createdAt ASC
    
    // 4. 限制新卡数量
    newCards = newCards.take(settings.dailyNewCardLimit)
    
    // 5. 交错合并：每 3 张复习卡插入 1 张新卡，避免疲劳
    queue = interleave(dueCards, newCards, ratio = 3 : 1)
    
    return queue
```

### 3.3 面试倒计时模式下的新卡插入策略

当用户开启面试冲刺计划时，系统除了在队列排序中提升高优卡片外，还会动态调整 **每日新卡上限** 与 **新卡选取范围**，确保在面试前覆盖所有必背内容。

**动态新卡上限计算**：

```
function dynamicNewCardLimit(settings, allNewCardCount, daysUntilInterview):
    baseLimit = settings.dailyNewCardLimit   // 用户设置的基础值，如 20
    
    if not settings.interviewMode or daysUntilInterview <= 0:
        return baseLimit
    
    // 计算如果按当前上限，剩余天数能否学完所有新卡
    neededPerDay = ceil(allNewCardCount / daysUntilInterview)
    
    // 取基础上限和所需量的较大值，但不超过最大阈值（如 50）
    adjustedLimit = min(max(baseLimit, neededPerDay), 50)
    
    return adjustedLimit
```

**高优先级卡片提前释放**：
- 将所有新卡按优先级降序排列后，取出 `adjustedLimit` 张作为今日新卡候选。
- 这样能保证最重要（高频或高难度）的卡片在前期就被纳入学习，后期不会因时间不足而遗漏。

## 4. 遗忘风险预判公式（可选，后期迭代）

为了在复习前警示用户哪些卡片正处在遗忘边缘，可以基于历史数据和当前状态计算 **24 小时遗忘概率**。

### 4.1 公式（简化逻辑回归模型）

```
risk = 1 / (1 + exp(-z))

其中：
z = β0 + β1 * (hoursSinceLastReview / 24) 
       + β2 * (lapses / max(reps,1))
       + β3 * (1.0 - EF/2.5)
```

- `hoursSinceLastReview`：距上次复习的小时数。
- `lapses / reps`：遗忘频率（生疏次数 / 总复习次数）。
- `EF`：当前难度系数，EF 越低卡片越难。
- `β0, β1, β2, β3`：系数，可通过用户群体数据拟合或使用默认经验值（如 β0=-1.5, β1=2.0, β2=1.5, β3=1.0）。

### 4.2 风险应用

- 当 `risk > 0.7` 时，标记为高风险，今日复习队列中靠前放置，并在卡片上显示红色预警图标。
- 睡前微复习功能仅推送高风险卡片的关键词提醒。

**注意**：该功能属于 v1.5+ 的增强特性，MVP 阶段不实现，但数据库与算法接口预留扩展能力。

## 5. 算法扩展性

调度算法被封装在 `Scheduler` 抽象类中，当前默认实现为 `SM2Scheduler`。未来可轻松替换为 FSRS、SSP 等其他间隔重复算法，只需实现相同接口：

```dart
abstract class Scheduler {
  ReviewState schedule(ReviewState state, int rating, 
      {bool interviewMode = false, double cardPriority = 0.0});
}
```

通过 Riverpod 提供 `schedulerProvider`，可在设置中切换算法实例，支持社区贡献新算法。
