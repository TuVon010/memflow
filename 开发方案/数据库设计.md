以下是 **MemFlow** 的本地数据库 Schema 设计，基于 Isar 数据库（纯移动端），完全对应 PRD 功能需求。

---

# MemFlow 数据库 Schema 设计 v1.0

## 1. 概述

- **数据库引擎**：Isar (NoSQL, 支持索引、关系)
- **存储位置**：App 私有沙盒目录
- **同步方式**：纯本地，通过文件导入/导出实现备份与迁移
- **设计原则**：扁平化集合，少量内嵌对象，通过 ID 关联，避免深层嵌套

---

## 2. 集合设计

### 2.1 Deck（卡组）

| 字段 | 类型 | 描述 | 索引 |
|------|------|------|------|
| `id` | `int` | 自增主键 | 主键 |
| `name` | `String` | 卡组名称 | |
| `description` | `String` | 卡组描述，可选 | |
| `color` | `int` | 主题色 (ARGB)，默认 0xFF4A90D9 | |
| `createdAt` | `DateTime` | 创建时间 | |
| `updatedAt` | `DateTime` | 最后修改时间 | |
| `isArchived` | `bool` | 是否归档，归档后卡片不参与复习 | |
| `priority` | `double` | 卡组优先级 (0.0~1.0)，用于面试倒计时排序 | |
| `tags` | `List<String>` | 全局标签（可选） | |

**关联**：
- 一对多关联 `cards`（通过 `deckId` 反向链接）

---

### 2.2 Card（卡片）

| 字段 | 类型 | 描述 | 索引 |
|------|------|------|------|
| `id` | `int` | 自增主键 | 主键 |
| `deckId` | `int` | 所属卡组 ID | 外键，索引 |
| `question` | `String` | 问题内容，支持 Markdown | |
| `answer` | `String` | 答案内容，支持 Markdown | |
| `cardType` | `String` | 类型：`basic`, `cloz`, `comparison`, `code` | |
| `sourceUrl` | `String` | 原始来源 URL（可选） | |
| `difficulty` | `double` | 卡片难度，由 AI 或用户标记 (0.0~1.0) | |
| `tags` | `List<String>` | 卡片级标签 | |
| `createdAt` | `DateTime` | 创建时间 | |
| `updatedAt` | `DateTime` | 最后修改时间 | |

**索引**：
- `deckId` (用于按卡组查询卡片)
- `cardType` (可选，未来可能按类型筛选)

---

### 2.3 ReviewState（复习状态）

每个用户对每张卡片的学习记录，驱动间隔重复调度。

| 字段 | 类型 | 描述 | 索引 |
|------|------|------|------|
| `id` | `int` | 自增主键 | 主键 |
| `cardId` | `int` | 关联卡片 ID | 唯一索引 `cardId` |
| `due` | `DateTime` | 下次复习到期时间 | 索引（用于查询待复习卡片） |
| `stability` | `double` | 记忆稳定性 (SM-17 系列参数，或 SM-2 间隔) | |
| `difficultyFactor` | `double` | 难度系数 EF (SM-2) 或 D (新算法)，默认 2.5 | |
| `reps` | `int` | 总复习次数 | |
| `lapses` | `int` | 遗忘次数（评分=生疏的次数） | |
| `lastReview` | `DateTime` | 上次复习日期 | |
| `nextReview` | `DateTime` | 实际计算出的下次复习日期（与 due 可相同） | |
| `reviewLog` | `List<ReviewLogEntry>` | 复习历史记录（内嵌对象列表） | |

#### 内嵌对象 ReviewLogEntry
| 字段 | 类型 | 描述 |
|------|------|------|
| `date` | `DateTime` | 评分时间 |
| `rating` | `int` | 评分：0=生疏, 1=犹豫, 2=顺畅 |
| `elapsedMs` | `int` | 从显示问题到评分的毫秒数 |

**索引**：
- `cardId` 唯一索引（一张卡片一个状态）
- `due` 索引（查询 `due <= now` 的卡片，按时间排序）

### 2.5 UserSettings（用户设置）

单例集合，仅存储一条记录。

| 字段 | 类型 | 描述 |
|------|------|------|
| `id` | `int` | 固定为 0 |
| `dailyNewCardLimit` | `int` | 每日新卡片上限，默认 20 |
| `dailyReviewLimit` | `int` | 每日复习上限（0 为不限制） |
| `preferredLLMProvider` | `String` | 首选 LLM 提供商标识 |
| `llmBaseURL` | `String` | API 基础 URL |
| `llmApiKey` | `String` | API 密钥（加密存储前明文，实际存储时会加密） |
| `llmModel` | `String` | 模型名称 |
| `interviewDate` | `DateTime` | 面试倒计时目标日期（可选） |
| `interviewModeEnabled` | `bool` | 是否开启面试倒计时模式 |
| `themeMode` | `int` | 0=跟随系统, 1=浅色, 2=深色 |
| `reviewReminderTimes` | `List<DateTime>` | 每日提醒时间列表 |

> **注意**：`llmApiKey` 实际存储时会加密，Isar 中存储为 `String`，加密解密由 `flutter_secure_storage` 配合代码完成。

### 2.6 ReviewSession（复习会话）

用于统计每日学习时长（P2 功能，可先占位）。

| 字段 | 类型 | 描述 | 索引 |
|------|------|------|------|

| `startedAt` | `DateTime` | 开始时间 | |
| `endedAt` | `DateTime` | 结束时间 | |

## 3. 关系与数据完整性

- **删除卡组**：级联删除其下所有 `Card`，以及对应的 `ReviewState`。
- **删除卡片**：级联删除其 `ReviewState`。
- **导入卡组**：深度复制卡组及其所有卡片，重新生成 ID，复习状态不导入。

## 4. 查询示例

### 4.1 获取今日待复习卡片
```dart
final now = DateTime.now();
final dueCards = await isar.reviewStates
    .filter()
    .dueLessThan(now, include: true)
    .sortByDue()
    .limit(50)  // 分页避免内存过载
    .findAll();
```
然后根据 `cardId` 批量加载对应的 `Card`。

### 4.2 获取某卡组内的所有卡片
```dart
final cards = await isar.cards
    .filter()
    .deckIdEqualTo(deckId)
    .findAll();
```

### 4.3 统计某天复习的卡片数
```dart
final count = await isar.reviewStates
    .filter()
    .lastReviewEqualTo(date)
    .count();
```

## 5. 数据库迁移策略

Isar 不支持自动迁移，版本升级时需手动处理：

1. 使用 `isar.schemaVersion` 判断当前版本。
2. 若版本不匹配，提示用户导出数据（JSON），清空旧库，执行新版本 Schema 创建，然后重新导入数据。
3. 在首个正式版本前，设计好稳定的 Schema，避免频繁迁移。

---

## 6. 加密与安全

- `llmApiKey` 字段在存入 Isar 前，使用 `flutter_secure_storage` 的真实存储方式。实际上，我们不在 Isar 中存储明文 Key，而是将 Key 单独存入系统钥匙串/KeyStore。`UserSettings` 表中仅保存除 Key 以外的配置。实施时，可在 App 中维护一个 `SecureStorage` 服务。
- 所有用户内容数据（卡片、卡组）不加密，保留明文便于用户通过文件系统直接访问（需 root 权限，普通用户不可见）。

## 7. 导出/导入 Schema

为了卡组的文件交换，定义 JSON 结构：

```json
{
  "version": "1.0",
  "exportedAt": "2026-07-25T10:00:00Z",
  "decks": [
    {
      "name": "Java Collections",
      "description": "",
      "color": 4289449321,
      "cards": [
        {
          "question": "What is the difference between HashMap and Hashtable?",
          "answer": "HashMap is not synchronized and allows nulls...",
          "cardType": "comparison",
          "difficulty": 0.5,
          "tags": ["java", "collections"]
        }
      ]
    }
  ]
}
```

导入时检查版本，并重新生成本地 ID，插入 `Deck` 和 `Card` 表，`ReviewState` 留空（全新卡）。
